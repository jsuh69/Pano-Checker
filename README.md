# Pano-Checker

M5StickS3(ESP32-S3)용 파노 모터 RPM·자력 측정 및 스톱워치 펌웨어입니다.

현재 버전: **v0.9.1**

## v0.9.1에 포함된 변경

- 위쪽 BtnB를 3개 모드 선택으로, 앞쪽 BtnA를 모드별 조작으로 재배치했습니다.
- 스톱워치 시작·정지·재개·긴 누름 리셋과 18pt 시간 표시를 추가했습니다.
- 녹음 완료 확인, 모드 전환 시 보정·검출 상태 초기화, 기상 버튼 중복 동작 방지를 적용했습니다.
- 외부 5V 승압 출력 비활성화, 센서 동작 구간 제한, 단계별 화면 절전 및 전원 진단을 적용했습니다.

## 조작 방법

v0.9부터 **위쪽 BtnB는 모드 선택**, **앞쪽 BtnA는 현재 모드의 기능 조작**을 담당합니다. 파워 버튼은 기존 전원 기능을 유지합니다.

| 입력 | PANO (파노 측정) | MAGNETIC (자력 측정) | STOPWATCH (스톱워치) |
| --- | --- | --- | --- |
| 위쪽 BtnB | 자력으로 전환 | 스톱워치로 전환 | 파노로 전환 |
| 앞쪽 BtnA 짧게 | LOW → MID → HIGH → VIB → LOW | 주변 자력 기준선 재보정 | 시작 / 정지 / 이어서 시작 |
| 앞쪽 BtnA 1초 이상 | 현재 센서의 AUTO 보정 | 주변 자력 기준선 재보정 | 정지하고 0으로 리셋 |

AUTO에서 앞쪽 버튼을 짧게 누르면 LOW로 돌아옵니다. 짧은 누름은 버튼을 놓을 때 확정됩니다. 스톱워치 시간은 해당 누름이 시작된 시각을 사용합니다. 길게 누른 뒤 놓아도 짧은 누름 동작이 추가 실행되지 않습니다.

화면이 꺼진 상태에서는 어느 버튼이든 첫 조작은 깨우기 전용입니다. 버튼을 놓은 뒤 다시 눌러 기능을 실행합니다. 모드 전환 중 누르고 있던 앞쪽 버튼도 놓기 전까지 새 모드의 동작을 실행하지 않습니다.

화면 상단에 현재 모드와 배터리 잔량·외부 전원 아이콘을 표시하고, 파노에서는 Hz와 감도도 표시합니다.

### 마이크 AUTO / 진동 AUTO 사용 방법

먼저 위쪽 **BtnB**로 `PANO` 모드를 선택합니다. AUTO 종류는 보정을 시작할 때 선택된 센서에 따라 정해집니다.

| AUTO 종류 | 앞쪽 BtnA 조작 | 측정 대역 |
| --- | --- | --- |
| **마이크 AUTO** | 짧게 눌러 `LOW`·`MID`·`HIGH` 중 하나 선택 → **1초 이상 길게 누르기** | 400–600 Hz |
| **진동 AUTO** | 짧게 눌러 `VIB` 선택 → **1초 이상 길게 누르기** | 150–750 Hz |

- `CALIBRATING`이 표시되고 약 1.5초간 보정한 뒤 `AUTO`로 바뀝니다. **보정 중에는 측정할 모터의 소리 또는 진동이 있는 상태를 유지하세요.**
- AUTO에서 BtnA를 **다시 길게 누르면 같은 센서로 재보정**합니다.
- AUTO에서 BtnA를 **짧게 누르면 LOW로 돌아갑니다.** 진동 AUTO에서 마이크 AUTO로 바꾸려면 LOW로 나온 뒤 길게 누릅니다. 마이크 AUTO에서 진동 AUTO로 바꾸려면 LOW로 나온 뒤 짧게 눌러 VIB를 선택하고 길게 누릅니다.
- 두 종류 모두 화면에는 `AUTO`로 표시되므로, 보정 전에 마이크 감도 또는 VIB 중 무엇을 선택했는지 확인하세요.
- AUTO는 피크 크기 기준을 보정하며 센서별 측정 주파수 대역은 바꾸지 않습니다.

## 저전력 동작

| 조건 | 화면 및 전원 정책 |
| --- | --- |
| USB 외부 전원 감지 | 밝기 25/255 유지. 자동 감광·화면 꺼짐·슬립 없음 |
| 배터리, 파노/자력에서 5초 무활동 | 밝기 3/255로 감소. 센서 측정은 계속 |
| 배터리, 파노/자력에서 20초 무활동 | 화면·마이크·IMU를 끄고 CPU light sleep |
| 배터리, 스톱워치 모드 | 마지막 버튼 조작 후 2분간 밝기 유지. 이후 화면을 끄고 light sleep |
| 화면이 켜진 상태에서 버튼 조작 또는 유효 RPM/자력 검출 | 밝기 복구 및 무활동 시간 초기화 |

- 파노·자력 처리는 **최대 초당 2회**입니다. AUTO 보정 중에도 분석 빈도를 높이지 않습니다.
- 마이크는 각 녹음 구간에만 켜고 프레임 사이에는 끕니다. 녹음 완료를 기다린 뒤 FFT를 수행합니다.
- 진동 센서는 VIB/AUTO-VIB에서만 켭니다. 자력·스톱워치에서는 마이크와 IMU를 모두 끕니다.
- CPU는 동작 중 80 MHz를 사용합니다. 화면이 꺼지면 클록만 낮추는 루프 대신 RAM을 유지하는 light sleep을 사용합니다.
- FFT는 `float`를 사용하고 Hamming 계수를 기동 시 계산해 재사용합니다. 정지된 화면은 상태·표시값이 바뀔 때 갱신합니다.
- Wi-Fi·Bluetooth·스피커·전원 LED를 사용하지 않습니다. 외부 5V 승압 출력도 기동 시 명시적으로 비활성화합니다.
- 스톱워치 STOPPED 상태는 버튼 확인을 약 50 ms 간격으로 줄이고, 표시 변경이 없으면 화면 갱신 함수를 호출하지 않습니다. CPU는 80 MHz를 유지하며 USB 연결 중에는 슬립하지 않습니다.
- 슬립 중에는 버튼으로 즉시 깨우거나 약 2초마다 USB 전원·배터리 상태를 확인하고 다시 잠듭니다. USB 양성 감지는 첫 표본부터 적용하고, 분리는 3회 연속 확인합니다. 케이블 연결 시 자동으로 화면을 복구합니다.

**센서가 꺼진 슬립 상태에서는 소리로 깨울 수 없습니다.** 소리에 의한 밝기 복구는 마이크 측정이 계속되는 감광 단계에서 유효한 모터 신호를 검출했을 때 동작합니다. VIB에서는 진동 검출을 사용합니다.

스톱워치가 다른 모드에서도 실행 중일 수 있지만, 화면 유지 시간은 현재 선택한 모드의 정책을 따릅니다. USB 연결 중에도 미사용 센서는 계속 꺼둡니다.

> 소비전력 감소량과 실행 중 순충전 여부는 아직 실기기에서 측정하지 않았습니다. USB 감지 아이콘은 실제 충전 전류나 충전 속도를 보장하지 않습니다. 외부 홀 센서의 전원은 GPIO로 제어하지 않으므로 연결 중 자체 소비전류는 남습니다.

## 스톱워치

- 표시: `시:분:초.1/100초`, 실행 중 화면은 최대 초당 10회 갱신합니다.
- 누적 시간은 화면 갱신과 독립적인 64비트 단조 시계로 계산합니다. 표시 자릿수와 실제 버튼 계측 정확도는 다릅니다.
- 모드를 바꾸거나 light sleep에 들어가도 실행 상태와 누적 시간을 유지합니다.
- 앞쪽 버튼을 길게 누르면 실행 중에도 정지·리셋합니다.
- 전원 종료·재부팅 시 기록은 초기화됩니다.

## 충전·전력 진단 (v0.9.1)

시리얼 모니터를 115200 baud로 열면 약 30초마다 아래 형식의 전원 상태를 출력합니다. 연결된 모니터가 없으면 진단용 I2C 읽기와 출력을 생략합니다. 송신 공간이 부족하면 전송을 나누거나 해당 주기 진단을 건너뛰며 버튼 처리를 기다리게 하지 않습니다.

```text
PWR usb=1 vin=5000 bat=4060 pct=95 chg=1 en=1 boost=0 imu=0 mic=0 watch=0
```

- `usb`: 앱이 판정한 외부 전원 연결 여부, `vin`/`bat`: 입력/배터리 전압(mV), `pct`: 표시 잔량.
- `chg`: 실제 CHG_STAT 핀 기준 충전 상태, `en`: PMIC 충전 허용 비트, `boost`: 외부 5V 승압 허용 비트.
- `imu`: BMI270 전원 제어 레지스터 값(정지 시 0), `mic`: 녹음 태스크 실행 여부, `watch`: 스톱워치 실행 여부.
- 레지스터 읽기 실패 또는 IMU 부재는 해당 필드에 `-1`로 표시합니다. `mic=0`은 마이크 전원 레일 차단을 의미하지 않습니다.

STOPWATCH / STOPPED에서는 보통 `boost=0 imu=0 mic=0 watch=0`, 충전 허용 시 `en=1`이 기대됩니다. `chg=0`은 완충에 따른 충전 종료일 수도 있습니다. CHG_STAT와 전압만으로 배터리 순충전 전류를 확정할 수는 없습니다. 자세한 원인 분석은 [전력 점검 기록](docs/POWER_REVIEW.md)을 참고하세요.

## 모드별 측정 주파수 대역

아래는 현재 v0.9.1 소스에 설정된 **피크 탐색 대역**입니다. LOW/MID/HIGH는 대역 선택이 아니라 검출 감도 선택이며, 모두 **400–600 Hz로 좁힌 동일 대역**을 사용합니다.

| 모드 / 옵션 | 센서 | 피크 탐색 대역 | 검출 조건 |
| --- | --- | --- | --- |
| PANO / LOW | 마이크 | **400–600 Hz** | 피크/잡음 비 12 dB 이상, 주파수가 일치하는 4개 연속 프레임 |
| PANO / MID | 마이크 | **400–600 Hz** | 피크/잡음 비 9 dB 이상, 주파수가 일치하는 3개 연속 프레임 |
| PANO / HIGH (기동 기본값) | 마이크 | **400–600 Hz** | 피크/잡음 비 6 dB 이상, 주파수가 일치하는 2개 연속 프레임 |
| PANO / VIB | BMI270 가속도 | **150–750 Hz** | 진동 피크 크기 및 300 ms 이상 연속 검출 조건 |
| PANO / AUTO (마이크에서 보정) | 마이크 | **400–600 Hz** | 보정한 피크 크기 범위, 피크/잡음 비 8 dB 이상, 3개 연속 프레임 |
| PANO / AUTO (VIB에서 보정) | BMI270 가속도 | **150–750 Hz** | 보정한 피크 크기 범위 및 300 ms 이상 연속 검출 조건 |
| MAGNETIC | GPIO 1 아날로그 홀 센서 | 주파수 분석 없음 | 주변 기준선 대비 자력과 N/S 극성 표시 |
| STOPWATCH | 센서 사용 안 함 | 주파수 분석 없음 | 시간만 계산하며 FFT·진동·자력 측정은 실행하지 않음 |

- **350–650 Hz는 마이크 잡음 추정용 참조 대역**입니다. RPM 검출 대역을 이 범위까지 넓히는 설정이 아닙니다.
- AUTO는 보정할 때 사용한 센서와 그 센서의 탐색 대역을 유지합니다. 주파수 대역을 자동 탐색하거나 넓히지 않습니다. VIB를 선택한 뒤 앞쪽 버튼을 길게 누르면 AUTO-VIB가 됩니다.
- 분석은 최대 초당 2회입니다. 마이크의 연속 프레임 주파수 허용 차이는 18 Hz이며, 감도와 분석 시작 시점에 따라 검출까지 대략 1–2초가 걸릴 수 있습니다.
- VIB의 150–750 Hz는 목표 탐색 대역입니다. 실제 수집 속도에서 분석 가능한 FFT bin 범위로 제한됩니다. 300 ms 연속 조건 역시 분석 프레임에서 확인하므로 300 ms마다 결과를 갱신한다는 뜻은 아닙니다.
- 대역 설정 위치: 스케치의 `Audio::kMicTargetBandLoHz/HiHz`(마이크), `Audio::kMicReferenceBandLoHz/HiHz`(잡음 참조), `processAudioAndFFT()`의 `searchBandLoHz/searchBandHiHz`(VIB).

## 측정 방식과 해석

- 마이크는 8 kHz / 1024 샘플을 수집하고 평균 제거·Hamming 윈도·FFT·피크 보간을 적용합니다.
- VIB는 목표 약 1600 Hz로 BMI270 가속도 벡터 크기 512개를 수집합니다. 평균 제거·Hamming 윈도 뒤 1024개로 zero padding하고 실제 수집 시간으로 주파수를 보정합니다.
- RPM은 `Hz × 60`입니다. 마이크의 400–600 Hz는 이 환산 기준으로 24,000–36,000 RPM에 해당합니다. 모터별 회전당 음향·진동 주기 수가 다르면 별도 보정이 필요합니다.
- AUTO는 약 1.5초간 보정 당시 피크 평균의 0.5배/3배를 하한/상한으로 설정합니다. 무신호 보정으로 잘못된 기준을 만들지 않도록 실제 검출 대상 신호가 있는 상태에서 보정하고 결과를 확인하세요.
- 자력은 GPIO 1의 32회 ADC 평균과 주변 기준선 차이를 사용합니다. Gauss 계수 `0.872`와 N/S 표시는 연결 센서·장착 방향에 맞춰 실측 검증해야 합니다.
- 배터리 %는 최근 3회 잔량의 중앙값입니다. 전압 기반 추정치이므로 USB 탈착 직후 바뀔 수 있습니다. 현재 라이브러리 계산에서는 약 4.10 V부터 100%로 표시되며, 표시 100%가 충전 종료를 뜻하지 않습니다. 펌웨어는 충전을 허용하고, 실제 종료는 충전 IC가 판단합니다.

## 빌드 및 업로드

Arduino IDE에서 `M5stickS3-motor-checker/M5stickS3-motor-checker.ino`를 열고 보드를 **M5StickS3**로 선택합니다. 같은 폴더의 `AppLogic.h`도 필요합니다.

v0.9.1 개발 환경: M5Stack 보드 패키지 **3.3.10**, M5Unified **0.2.26**, arduinoFFT **2.0.4**. CLI 보드 식별자는 `m5stack:esp32:m5stack_sticks3`입니다.

```sh
arduino-cli compile --fqbn m5stack:esp32:m5stack_sticks3 M5stickS3-motor-checker
```

설치된 도구가 현재 Mac CPU와 맞지 않으면 `bad CPU type in executable` 오류가 발생합니다. 해당 도구의 호환 버전이 필요합니다.
