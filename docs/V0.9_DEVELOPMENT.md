# v0.9 개발 및 검증 가이드

## 구조와 변경

`M5stickS3-motor-checker.ino`가 하드웨어/버튼/센서/화면/전원을 제어하고, 같은 폴더의 `AppLogic.h`는 하드웨어와 독립적인 스톱워치, 앞쪽 버튼 제스처, 화면 전력 정책을 정의한다.

- BtnB 모드 전환: PANO → MAGNETIC → STOPWATCH → PANO.
- BtnA 모드별 동작: 감도/AUTO 보정, 자력 기준선 보정, 시작·정지·리셋.
- `sMeasurementGeneration`은 모드/감도/보정/절전 전환 시 증가한다. 수집 중 변경되면 이전 프레임을 폐기하고 새 모드에 결과를 반영하지 않는다.
- 모드/감도 전환과 절전 시 마이크 추적·진동 연속 검출·마지막 Hz를 초기화한다. 모드 전환 시 진행 중 보정을 취소한다.
- 기상과 모드 전환 시 버튼을 모두 놓기 전까지 이벤트를 소비한다. 긴 누름 뒤 짧은 동작도 억제한다.
- `M5.Mic.record()` 후 `isRecording()` 완료를 기다린다. 대기 중에는 yield와 버튼 처리를 실행하며 500 ms 제한을 둔다. 실패 시 녹음을 종료하고 SENSOR ERROR를 표시한다.
- BMI270 누락/불완전 수집은 FFT에 넣지 않는다. 자력 보정 후 필터를 초기화한다.
- 내부 센서·코덱·PMIC는 `M5.In_I2C`를 공유한다. Wire/Wire1으로 같은 버스를 재초기화하지 않는다. 마이크 핀/코덱 설정도 M5Unified 보드 설정을 사용한다.
- 500 ms 분석 시작 간격을 보정 중에도 유지한다. UI 갱신은 분석 주기와 분리한다.
- 마이크는 녹음 구간에만 활성화한다. FFT는 float로 전환하고 창 계수를 캐시했다.
- USB 외부 전원 감지와 실제 충전 중 상태를 혼동하지 않도록 읽기 인터페이스를 `hasExternalPower()`로 명명했다.
- 밝기 25→3→화면 off/light sleep 정책은 배터리 사용 시만 적용한다. 스톱워치는 120초 후 off, USB는 항상 밝기 유지/슬립 금지다.
- 슬립 중 2초 타이머 및 GPIO 11/12의 LOW 레벨로 기상한다. 타이머 기상은 배터리·USB를 확인한 뒤 화면 off를 유지하고 다시 잠든다. 버튼/USB 기상은 화면을 복구한다. GPIO 깨우기 설정 또는 슬립 실패 시 버튼 폴링으로 대체한다.
- `esp_timer_get_time()` 기반 64비트 ms로 스톱워치를 계산한다. 화면 갱신 횟수와 무관하며 light sleep 경과 시간을 포함한다.

## 로컬 자동 검증

```sh
bash tests/run-host-tests.sh
# arduinoFFT가 기본 Arduino 라이브러리 폴더에 없다면:
bash tests/run-host-tests.sh /path/to/arduinoFFT/src
arduino-cli compile --fqbn m5stack:esp32:m5stack_sticks3 M5stickS3-motor-checker
```

로직 테스트 범위: 짧은/긴 누름 구분, 긴 누름의 중복 실행 억제, 전환/기상 시 제스처 취소, 스톱워치 누적·정지·재개·리셋, 슬립 동안 시간 경과, 32비트 ms 경계 이후 계산, 5/20/120초 전력 정책 경계, USB/보정 중 밝기 유지.

통합 회귀 테스트는 실제 스케치를 호스트에서 실행하되 M5 보드·GPIO·시간·녹음 장치만 모의 구현한다. arduinoFFT는 실제 라이브러리를 사용한다. 알려진 500 Hz 검출, 무음·대역 밖 신호 배제, 녹음 완료 전 FFT 방지, 녹음 타임아웃, 마이크/진동 수집 중 모드 전환 취소, 앞쪽 버튼 리셋/기상 이벤트 소비, USB 자동 기상 및 분리 확인, 자력 필터 초기화, IMU 통신 실패, 스톱워치 모드의 센서 호출 없음, AUTO 보정 중 초당 최대 2회 분석을 확인한다.

펌웨어 컴파일 및 최종 검증 결과는 아래 검증 기록에 남긴다. 로직 테스트가 센서/전력 하드웨어 동작을 보장하지는 않는다.

## 실기기 확인 순서

1. 상단 모드 이름·배터리·USB 아이콘과 Hz/감도가 겹치지 않는지 확인한다.
2. 위쪽 버튼으로 3개 모드를 순환하고 앞쪽 짧게/1초 이상 동작을 각각 확인한다. 두 버튼을 같이 누르거나 보정 중 전환해도 동작이 섞이지 않아야 한다.
3. 스톱워치를 기준 시계와 비교한다. 정지/재개, 실행 중 리셋, 모드 전환, 2분 슬립 후 시간 보존을 확인한다. 정지 버튼 누름 시각을 기록하는지 확인한다.
4. 배터리에서 파노/자력은 5초 감광·20초 off, 스톱워치는 120초 동안 밝기를 유지하는지 확인한다. 스톱워치 실행 상태 자체는 무활동 타이머를 리셋하지 않는다.
5. 버튼 기상 후 놓는 동작이나 길게 누르고 있는 동작이 감도 변경·리셋·모드 전환을 일으키지 않는지 확인한다.
6. USB 연결은 약 2초 이내 감지하여 화면을 복구하고, 연결 중 2분 이상 감광/off/슬립이 없는지 확인한다. 분리 후 약 4–6초의 확인 시간을 거쳐 새 무활동 타이머가 시작되는지 확인한다.
7. 알려진 400/500/600 Hz 신호와 무신호·충격음을 비교한다. 녹음 구간마다 마이크를 재기동하므로 코덱 안정화 잡음·검출 누락 여부를 확인한다. 필요 시 녹음 앞부분을 버리는 안정화 구간을 추가하되 전류와 함께 측정한다.
8. VIB 모드에서 통신 실패와 모드 변경 시 불완전 프레임이 표시되지 않는지 확인한다. 센서 부재 시 SENSOR ERROR가 표시되고 절전에 들어갈 수 있어야 한다.
9. 자력 재보정 뒤 이전 Gauss 값이 남지 않는지 확인한다. 표준 자장/센서 사양으로 계수와 극성을 검증한다.
10. 동일한 배터리/케이블/USB 전원에서 v0.8과 v0.9의 파노 측정·감광·스톱워치·슬립 전류, USB 연결 중 배터리 순전류를 비교한다. 소프트웨어 정책만으로 충전 전류 증가나 배터리 수명을 확정하지 않는다.

## 남아 있는 한계

BMI270은 목표 간격으로 레지스터를 읽으며 data-ready/FIFO 동기화를 도입하지 않았다. 평균 Fs 보정만으로 비균일 간격·중복 샘플 문제를 해결하지 못한다. RPM 환산의 회전당 주기 수와 자력 계수는 기종별 검증이 필요하다. GPIO 1 홀 센서의 전원은 외부 배선에 따라 계속 공급될 수 있다.

## 검증 기록

- 로직 테스트: 통과.
- 모의 보드 + 실제 FFT를 사용하는 통합 회귀 테스트: 통과.
- M5StickS3 대상 펌웨어 컴파일: 통과. 프로그램 1,180,711 bytes(35%), 정적 메모리 62,488 bytes(19%).
- 실기기 업로드: 후속 IDE 검증에서 성공(아래 기록). 전류/계측 정확도 측정: 미수행.

최초 검증 시 이 Mac의 ESP32 컴파일러와 ctags가 Intel 실행 파일이어서 실행되지 않았다. 임시 폴더에 ARM64 ESP32 컴파일러를 내려받아 공식 패키지 SHA-256을 확인했으며, Arduino ctags 5.8-arduino11은 현재 Mac SDK와 충돌하는 예약 매크로 이름만 변경하여 로컬 빌드했다. 최초 검증에 사용한 도구 경로 지정 명령은 아래와 같다.

```sh
arduino-cli compile --fqbn m5stack:esp32:m5stack_sticks3 \
  --build-property runtime.tools.esp-x32.path=/private/tmp/pano-xtensa-arm64 \
  --build-property runtime.tools.ctags.path=/private/tmp/pano-ctags \
  --build-property tools.ctags.path=/private/tmp/pano-ctags \
  --build-path /private/tmp/pano-checker-v09-build M5stickS3-motor-checker
```

### Arduino IDE 설치 도구 복구 (2026-10-20)

이후 IDE에서도 같은 CPU 오류가 발생하여 설치 경로의 ESP32 컴파일러와 ctags를 검증된 ARM64 도구로 교체했다. 기존 Intel 도구는 `/Users/jinsunuh/Library/Arduino15/pano-tool-backups/20261020-125555`에 보관했다. 도구 경로를 별도로 지정하지 않는 일반 빌드도 성공했다(프로그램 1,180,711 bytes, 정적 메모리 62,488 bytes). 보드 패키지나 Arduino 도구를 재설치/업데이트하면 설치 파일이 다시 교체될 수 있으므로 CPU 호환성을 확인해야 한다.

후속 확인에서 IDE 자체의 `Done compiling`을 확인했다. 포트 검색 도구(`serial-discovery 1.5.2`, `mdns-discovery 1.1.0`)와 `serial-monitor 0.15.0`도 Intel 실행 파일이어서, 공식 ARM64 패키지를 내려받아 SHA-256 검증 후 교체했다. 기존 파일 백업: `/Users/jinsunuh/Library/Arduino15/pano-tool-backups/20261020-130515-discovery`. IDE 재시작 후 `/dev/cu.usbmodem1101` 포트가 인식되고 M5StickS3 보드와 함께 선택된 것을 확인했다.

IDE 후속 실기기 업로드: `/dev/cu.usbmodem1101`에서 쓰기와 `Hash of data verified`, `Hard resetting via RTS pin...`, `Done uploading.`을 확인했다. 실제 센서/스톱워치 조작과 전류 측정은 별도 검증 대상이다.

### v0.9.1 전력 수정

외부 5V 출력 기본값을 명시적으로 끄고 STOPPED 상태 반복 처리를 줄였다. USB 화면 유지/슬립 금지 정책은 유지한다. 충전·전원 레지스터 진단은 시리얼 모니터 연결 시 30초마다만 수행한다. [전력 점검 기록](POWER_REVIEW.md)과 README의 진단 필드 안내를 참고한다.

회귀 테스트에는 기본 외부 출력 비활성화, STOPPED 버튼 확인 주기, 모니터가 없을 때 추가 센서 읽기 없음, 진단 주기 제한, 64바이트 TX 공간에서 분할 출력, 레지스터 오류 표시 및 TX 혼잡 시 읽기 생략을 추가했다.

v0.9.1 검증: 호스트 로직/통합 회귀 테스트와 M5StickS3 컴파일 모두 통과했다. 프로그램 1,186,619 bytes(35%), 정적 메모리 62,696 bytes(19%). 이번 수정은 소스·문서에만 반영했으며 기기 업로드와 전류 측정은 수행하지 않았다.
